# 实现、依赖边界与注释规范

## 独立工程

`rhythm-dnb-core` 从既有科研工程提取，Python 包为 `rhythm_dnb`。发布源码包含 70 个生产 Python 文件；算法实现与提取前核验版本逐字节相同。旧仓库、数据库和 APP 不受此提取影响。

六个历史来源解析器位于 `io/sources/`，只接收显式路径。`legacy_schema.py` 隔离历史宽表契约；旧时间锚、已有诊断和相对日期不能自动成为新协议的前瞻性观测。`audit` 只读外部数据库。

正式观测必须提供时区、完整时间、实际可得时间、单位与来源哈希。独立 SQLite 存储支持事务、唯一预测、不可覆盖日面板版本、as-of 特征查询和追加审计。

## 目录拆合理由

`dnb/statistics` 共享行筛选、相关与分数组合；classic/single_sample 分开，因为样本轴和统计意义不同。measures 按采集域分开，scaling/panel 共享。outcomes 与 warning 分离，避免未来标签进入推理。research 供离线发现、校准、对照和评估；workflows 编排这些步骤。text/checkpoint 独立于 train，推理不必导入训练或语料数据库。

将来服务层直接调用 `RhythmPredictor`，在业务层持久化 `AlarmState` 与幂等响应。当前源码不包含 APP、网页或 HTTP 服务。

## 注释与验证

生产函数使用英文 `PSEUDOCODE` 注释概述步骤；模块与 docstring 解释变量、单位、形状、缺失与科学假设。跨午夜、抽样和信息泄漏等分支解释原因。中文使用说明保存在文档。

测试覆盖已知解析解、符号/平移/尺度性质、午夜/DST、SRI/IS/IV、数据来源、参考人数、候选枚举、空模块结果、未来证据、冻结产物、冷却期、事件随访、聚类重采样和文本训练/推理。

迁移兼容性测试读取冻结的合成数值夹具，无需旧仓库。微型本地 BERT 测试执行实际训练、保存、重新加载和连续输出，不下载外部模型，不代表训练出了可用的真实预警器。

`tools/review_research.py` 扫描源文件、配置、测试、数值常量、导入和注释，并生成明确标注的合成诊断。原始数据库仅由显式参数提供。扫描输出不等于形式化正确性证明。

研究产物另外固定 config、seed、参考/模块/阈值哈希及文本权重哈希。不同研究设置保存独立 bundle。线性、二/三阶样条和提升树在开发集按人交叉验证，独立测试数据不参与模型选择。
